# keel-decl

Test edges (`stands_on`, `joins`) are declared on the test function and recorded by the `keel-macros` attributes as a small `#[used]` static in a dedicated link section of the test binary (`.keel` on ELF and PE/COFF, `__DATA,__keel` on Mach-O); this crate defines the record format and reads it back with the `object` crate. The binary needs no custom test harness (plain libtest and nextest keep working unchanged) and can be read without running it, so the framework learns the hierarchy before it spends a second executing tests. The cost at runtime is one address load per test invocation, not zero: `#[used]` alone only stops the compiler discarding the static, and a linker running section garbage collection (`--gc-sections` on ELF, `/OPT:REF` on PE) may still drop a `.keel` section nothing refers to, so the macro also inserts `let _ = black_box(addr_of!(RECORD));` at the top of the test function. That reference is a relocation from the test function, which the harness's test table keeps reachable, to the record, so every linker keeps the section for as long as it keeps the test. This is the one approach that works on stable Rust on every platform without `#[used(linker)]` (nightly) or section-name games such as a C-identifier name that exploits `__start_`/`__stop_` retention. The one caveat is that a test whose crate is never linked into a test binary leaves no record and is invisible to the reader; that is correct, because such a test does not exist in any binary that could run it. A related consequence is that a declaration on a non-test function lands in every binary that links that function, so consumers should pair each binary with its crate root and discard foreign records (`try_nextest_test_name` returns `None` for them). Finally, a record names a function, and one function can expand into several tests (`rstest` cases are `<fn>::case_1`, ...); use `applies_to` to match a declaration against nextest names.
